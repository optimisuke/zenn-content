# はじめに

[テックルズ](https://techls.org/)で、経済産業省こどもデー(7/29・7/30)向けに4コマ漫画生成アプリ「どやねん.ai!」を作りました。人が1コマ目と3コマ目を描いて、AIが2コマ目と4コマ目を描くアプリです。

イベントが終わったので、そろそろこのアプリは止めようと思っています。ちょうど一周したので、今回の**週末?プロジェクトをAIとどうすすめたか**を振り返っておきます。

規模はこれくらいでした。

- 準備期間: 1ヶ月ほど。週末にたまに進める感じ
- 実働開発時間: ちゃんと計算してないけど、10時間以上20時間未満くらい
- 体制: エンジニア1人(自分) + デザイナー3人
- 使った場所: イベント2日間、子どもたちが実際に描いて生成

作りながら考えたContext Engineeringの話は別記事に書いたので、こちらでは**進め方とインフラの判断**を中心に書きます。

https://zenn.dev/optimisuke/articles/c4e91a7b2d6f30

# どんな動きをするアプリか

トップはこんな感じです。

![](/images/e9d1ac3bd47482/top.png)

「AIといっしょにつくる」を押すとSTEP1。紙に描いた絵をカメラで撮るか、画像をアップロードします。

![](/images/e9d1ac3bd47482/step1-wait.png)

撮ると向きの確認が入って、OKするとAIが1コマ目を読んでコメントを返します。「はんばーがー、めっちゃおいしそうやん！」みたいなやつです。ここは絵を評価せず、描いた人の意図をやさしく受け取るようにプロンプトで縛っています。

![](/images/e9d1ac3bd47482/step1-comment.png)

STEP2でAIが2コマ目を描きます。ここで待ち時間がそこそこあって、体感で30秒。ワークショップだと会話していたら割とすぐかなとは思いました。ただ、気になったので、**次のコマの企画(どういう展開にするか、どんな絵にするか)は1コマ目のアップロード時に前倒しで走らせておいて、STEP2の待ちを画像生成だけにする**構成にしました。

![](/images/e9d1ac3bd47482/step2-loading.png)

出てきた2コマ目。ハンバーガーがぷるぷるしはじめました。

![](/images/e9d1ac3bd47482/step2-done.png)

STEP3は人の番。AIが出した展開に人が乗っかっていきます。

![](/images/e9d1ac3bd47482/step3.png)

STEP4でAIがオチを描きます。1〜3コマ目を全部参照させているので、ハンバーガーが「たすける係」のヒーローになりました。ちょっと、微妙ですね。。。**四コマ漫画ドメイン知識（四コマ漫画を書く能力）が足りないのでプロンプトの改善がこれ以上難しかったです。。。ドメイン知識が大事ですよねー。**

![](/images/e9d1ac3bd47482/step4.png)

STEP5で4コマ並べて、最後の一言(「バーガーさん、きょうから たすける係！」)を出して完成。もうちょいなんとかならんかったかなー。。。QRを出すとその場でスマホから見られて、ギャラリーにも並びます。

# 意識していたコンセプト

技術の話に入る前に、何を確かめたかったかも書いておきます。テーマは「AIと人との協業」で、気にしていたのはこのあたりでした。

- AIで人の創造性を増幅できるか
- AIとやりとりしたとき、人はどんな反応をするか
- クリエイティブな領域でAIと人が協業する形は成立するか

なので、人が1・3コマ目、AIが2・4コマ目、と交互にしました。AIのコマにも「なぜこの展開にしたか」を残して見せるようにしました。**また、自然につながるように、まずは人が書いて、そのテイストを真似するようにしています。**

イベントで見ていておもしろかったのは、AIが変な展開を出したときに、子どもがそこに乗っかっていくところでした。さっきの3コマ目の「なんなんおまえ！」みたいに、AIが投げた球に人が反応して、次の球が変わっていく感じがありました。増幅できたかどうかを評価できているわけではないですが、**交互にやりとりすることは成立していた**気がします。イベントの参加者の方にも概ね楽しんでもらえたたかなーと思います。

# どこまで本気の構成にするか

実働10〜20時間の週末プロジェクトで、しかも数日のイベントで使うだけなので、非機能要件はゆるめに進めれました。

- 最初はSQLite + ローカル
- 割とすぐPostgreSQLに移して、Docker Composeでローカルを回すように
- ある程度動いた段階でAzureへのデプロイに移行(Container Apps + Terraform + GitHub Actions)
- ドメインはCloudflareで、設定はAIにコマンドを打ってもらった

CICDやTerraformでのGitOpsを早めに指示することで、チームで動作確認しながらすすめることができました。AIがいい感じに作ってくれるので、一般的に「やるべきこと」を知ってることが大切だなと感じます。**AIに聞けば教えてくれると思いますが、聞かないと教えてくれないのが難しいところだなーと思います。**

環境変数はけっこう悩みました。結局、ローカルは`.env.local`、CIはGitHub ActionsのSecrets、本番はAzure側のsecretという3箇所に分かれて、そこそこ試行錯誤しました。最適解はよく分かってないですが、この規模だと問題にはならなかったです。

コストは月あたりでこんな感じでした。

- Azure OpenAI: 4000円くらい
- PostgreSQL / Container Apps / Container Registry: 合わせて5000円くらい

最初はContainer Appsを`min_replicas=0`にしてアイドル時のコストを抑えていましたが、イベント直前はチームで動作確認する頻度が上がったので、コールドスタート待ちが煩わしくなって`min_replicas=1`にしていました。もうちょい安くできた気もしますが、こんなもんかーという感じです。今回、Azure試してみたかったので、Azureでしたが、CloudflareとかVercelとか他のクラウド使ったほうが安い気はしてます。

# コードの中身はほとんど読んでいない

進め方は、`TASKS.md`にタスクを足したり消したりしながらAIに仕事を振る、というやり方でした。仕様は`SPEC.md`に書いて、決まったら更新していく感じでした。

また今回、**コードの中身はほとんど読んでいません**。`SPEC.md`に書いてある内容を見て、だいたい動いてるからいいか、という気持ちで走り切った感じです。

これができたのは、たぶん「数日のイベント用」という前提があったからだと思います。長く運用するなら、どこかで中身をもう少し把握しないと非機能要件で詰む気がしますが、今回はそこに時間を使わないという判断でした。

# デザイナー3人から来たものが、そのままAIへの入力だった

実装はほぼエンジニアの私1人でやったので工数としては自分がそこそこ大きいのですが、渡ってくるものの形がAI前とは全然違いました。みなさんも感じているところかとは思いますが。

- デザイナーA: AIとReactでモックアップを作る
- デザイナーB: `DESIGN.md`を書く
- デザイナーC: アプリのプロンプトを考える
- 自分: それらを参照しながらAIに実装させる

前だったら、デザイナーからは画面のデザインが来て、それをエンジニアが実装する、という形が多かったと思います。今回渡ってきたのは「動くモック」「テキストで書かれたデザイン方針」「プロンプト」で、**どれもそのままAIへの入力になるもの**でした。デザイナーとエンジニアって呼んでますが、違う呼び方にしちゃってもよいのかもです。

# AIに任せきれなかったこと

テストコードは積極的にAIに書いてもらいました。単体・結合・E2Eをできるだけやってもらう方針でしたが、細かいところは見ていないので、**それで十分だったかの評価まではできていません**。

一方で、見た目の修正は実際にけっこう手を入れました。人間が使ってみてどう感じるかは、やっぱり人がやらないと難しいなと感じています。ただこれは、ターゲットユーザーや使われ方をもっとちゃんと伝えていれば、UI改善の提案もAIにしてもらえたのかもしれない、とも思います。

ライブラリの更新はDependabotで、上がってきたPRをローカルのAIに確認してもらってマージする形にしていました。GitHub連携でクラウド上でチェックしてマージまで、という仕組みにしてもよかったかもですが、そこまではやっていません。

AIの使い方としての一番の反省は、**並列に動かせなかった**ことです。せいぜい2画面くらい開いてターミナルで並行させるのが限界で、待ち時間がそこそこ出ました。プロジェクトが小さいからしょうがない部分はあると思いつつ、もっと工夫できそうな気はしています。実働10〜20時間のうち、実は半分以上待ち時間やった気もしてます。。。

# おわりに

今回、週末プロジェクトで、実働10〜20時間あればイベントで使えるものが作れました。振り返ると、「早めに本番構成に寄せた」「中身を読まないと決めた」ことで、それなりに速く作れたかなーと思ってます。

アプリを止めるところまで一周してみて、これくらいの規模ならこの進め方はしっくりきている気がしてます。他にもおすすめのやり方等、フィードバックあればお願いします。
