# はじめに

以前、イベント向けにAIと人が交互に4コマ漫画を描くNext.jsアプリを作りました。
インフラはAzure Container Apps + PostgreSQL Flexible Server + Blob Storageで構成して、Terraformで管理していました。イベント期間中は問題なく動いたんですが、月々の費用がそこそこかかりました。

https://zenn.dev/optimisuke/articles/e9d1ac3bd47482

| 項目                                             | 月あたり          |
| ------------------------------------------------ | ----------------- |
| Azure OpenAI                                     | 4,000円くらい     |
| Container Apps / PostgreSQL / Container Registry | 5,000円くらい     |
| **合計**                                         | **9,000円くらい** |

次のイベントに向けてアプリを動かし続けることになって、「Azureのままだと月9,000円は結構たかいなー」と思って移行することになりました。最終的にVercel使うことにしてOpenAI APIのコスト以外は、ほぼゼロになりました。

| 項目                          | 月あたり                        |
| ----------------------------- | ------------------------------- |
| Vercel / Neon / HCP Terraform | 無料枠の範囲                    |
| OpenAI API                    | Azure OpenAI とたぶん同じくらい |
| **インフラ費**                | **ほぼゼロ**                    |

AI APIの費用はまだはっきりしていませんが、おそらく変わらないくらいです。インフラ費の5,000円がほぼゼロになるのが大きいです。

ただ、これは**個人の非商用プロジェクト**という前提のコストです。後述しますが、商用利用を考えると、正直そこまで変わらなさそうな感じがします。別の方法考えた方が良いかもです。

この記事では、移行の判断過程、Terraform stateの置き場所の話をまとめます。

# 移行先の選定：CloudflareかVercelか

最初に「CloudflareとVercelどっちにしようかなー」と迷いました。

Cloudflareはドメイン管理で利用しており、Vercelは使ったことがありました。

Cloudflareを検討しはじめて「Cloudflare D1はPostgreSQLとなにがちがうんやろ？」「Hyperdrive？？？」となりました。
はじめからCloudflareならいいですが、Cloudflareに移行しようとするとそこそこ考えることが増えそうでした。

このアプリはすでにNext.js App Routerで作っていたので、Vercelを選ぶとnative buildとNeon（PostgreSQL）・Vercel Blobがそのまま組み合わせやすそうでした。ということで、移行時の差分が少ないので、Vercelにしました。

移行前後の対応はこうなりました。

| 責務            | Azure版                          | Vercel版                            |
| --------------- | -------------------------------- | ----------------------------------- |
| Next.js hosting | Azure Container Apps             | Vercel（Functions + static assets） |
| Database        | Azure PostgreSQL Flexible Server | Neon PostgreSQL                     |
| 画像保存        | Azure Blob Storage               | Vercel Blob                         |
| AI              | Azure OpenAI                     | OpenAI API                          |
| DNS             | Cloudflare                       | Cloudflare（継続）                  |

# Terraform stateの置き場所

AzureではTerraform stateをAzure Blob Storageに置いていました。

```hcl
terraform {
  backend "azurerm" {
    resource_group_name  = "<state-resource-group>"
    storage_account_name = "<state-storage-account>"
    container_name       = "tfstate"
    key                  = "app.tfstate"
  }
}
```

Vercelに移行したあとも、stateのためだけにAzureのStorage AccountとCredentialを維持するのは避けたかったです。

「Vercel Blobにstateを置けばいい？」とも思いましたが、Terraform backendに求められるのはlockingやstate履歴の管理らしく、アプリ向けObject Storageとは責務が違うようです。Vercel Blobは公式のTerraform backend対応はしていないようでした。そこに独自実装でstateを置くのは時間的に合わなそうでした

そこで最終的に **HCP Terraform** を選びました。本家のTerraformマネージドサービスです。

HCP Terraform 使うにしてもいくつか選択肢があるのですが、Execution Modeを`Local`にする構成にしました。Execution Modeの`Local`は「ローカルPCで実行する」という意味ではなく、「plan/applyはTerraform CLIを起動した場所（今回はGitHub Actions）で実行し、state管理だけHCP Terraformに任せる」という構成です。

```
GitHub Actions runner → plan / apply（実行）
HCP Terraform Workspace → state / lock / 履歴（管理）
```

GitHub Actions側にすでにapprovalやsecretの仕組みがあったので、plan/applyまでHCP側に寄せるRemote executionにはしませんでした。既存の運用を大きく変えずに済んだのがよいなと思いつつ、HCP Terraformに寄せるのもありかもなとは思います。

なおHCP Terraformを選ぶとき、「Free planがなくなる」みたいな記事を見かけてましたが、旧Legacy Freeの終了の話で、現行のプランにはFreeの枠が残っていました（作業時点でEnhanced Freeで最大500 managed resources）。

# コストの注意点

移行する際に気をつけた方が良いのが、**Vercel Hobby planは非商用利用限定**という点です。今回は個人プロジェクトなので問題ないですが、仕事や商用サービスで使う場合はPro plan（$20/月〜）が必要になります。そうなると今の利用頻度だとAzureとそこまで変わらない気もします。

Neonの無料枠についても、セキュリティ面の制約があります。IP制限や監査ログなどは有償プランの機能なので、個人情報を扱うサービスや本番運用では無料枠で済ませるのは厳しいと思います。今回は趣味プロジェクトなので許容しましたが、用途によっては有償プランを最初から前提にした方がよさそうです。

あと、インフラ費がゼロになっても、AI APIの費用は画像生成の利用量に比例して上がります。今回はそこが変わらないくらいなので全体としては下がりますが、利用頻度が増えるとAI API費が全体を支配するようになります。

# おわりに

個人の非商用プロジェクトという前提では、Vercel + Neon + HCP Terraformはいい感じの選択肢でした。HCP Terraformは省略してもよいかもですが、VercelのリソースもTerraformで管理したい人はおすすめです。全体として、「使わないときはコストがかからない」という点がありがたいです。

一方で、Hobby plan・無料枠の制約はちゃんと把握してから使う必要があります。当たり前ではありますが、商用利用や本番サービスに転用するときは、プランや料金体系を改めて確認しないとです。

Terraform stateの置き場所をHCP Terraformに移したのは地味な話ですが、Azureを完全に切り離せたのでお気に入りの判断です。state管理だけmanaged serviceに任せて、plan/applyの運用は変えないというのはバランスが良さそうです。
